The package snapshot comes from the public [Legacy game page](https://sbox.game/limestudio/legacy). Package-page values can change at any time and are stored with a retrieval timestamp rather than fetched in every visitor's browser.

## Public leaderboard API

s&box officially documents public stat-backed leaderboard reads at:

`https://public.facepunch.com/sbox/package/{ident}/leaderboard/{stat}/`

Legacy's package ident is `limestudio.legacy`. The inspected source reports:

- `total-years-lived`
- `lifespan-years`
- `total-rebirths`
- `touch-eye-rebirths`
- `embrace-evil-rebirths`
- `transcend-rebirths`
- one `empire-years-{property-id}` stat per property

The wiki's scheduled workflow reads only the three summary leaderboards, uses `aggregation=last`, and builds the response into static JSON. It needs no private API key. A failed refresh does not delete the previous snapshot.

## Reliability boundary

The public leaderboard endpoint is documented and suitable for build-time reads. The richer package metrics shown by the game page do not have an equally clear, documented browser API in the investigated public documentation. They therefore remain a timestamped package-page snapshot instead of an aggressive scraper or client-side dependency.
